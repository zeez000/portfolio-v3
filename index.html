    E-commerce platform case study

    Drawn from the repository README.

    The problem

    A stock check done with plain REST calls couples every service to every other. The project explores what changes when services only share events.

    Why microservices and Kafka

    Product, Inventory and Order are separate services. Product Service publishes product.created and never calls Inventory, which creates a stock record from the event. Kafka runs in KRaft mode, so no ZooKeeper.

    Event flow

    Order Service stores a pending order and publishes order.created. Inventory reserves stock and publishes inventory.reserved or inventory.rejected. Every event carries the order ID, so two pending orders for one product cannot update each other.

    Data

    MongoDB holds products, inventory and orders. Redis caches the product list for 60 seconds and is invalidated on writes. Stock reservation is a conditional update, so two concurrent orders cannot both take the last item.

    Container networking

    In Compose, services reach each other by service name (mongodb, kafka). localhost inside a container means that container only.

    CI pipeline

    On push and pull request: install, validate Compose, build images, start the whole stack, wait for a healthy gateway, run scripts/smoke-test.sh, and print container logs on failure. Images publish to GHCR from main.

    Health checks and testing

    Every service has /health for traffic decisions and /metrics for Prometheus. The smoke test walks product, inventory, order, reservation and confirmation, then checks the stock count. The README lists unit tests as a gap.

    Troubleshooting

    In a Codespace, service names resolved but container-to-container TCP timed out. The cause was a stale iptables-legacy FORWARD policy dropping traffic on Docker's bridge networks while Docker used iptables-nft. The repo includes an idempotent repair script.

    What I would improve next

    Authentication and TLS, Kubernetes Secrets, dead-letter queues, idempotent consumers, real application metrics, unit tests, and Terraform with an AWS deployment. The Kubernetes manifests are in the repo, and the README lists local cluster testing as a next step.
